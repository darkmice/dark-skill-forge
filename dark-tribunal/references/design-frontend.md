# UI Designer / Frontend Builder / Frontend Reviewer

仅在 UI、交互、客户端状态或前端代码受到影响时加载。纯后端任务将这些视角标记为 `N/A`。

## 规则优先级

按以下顺序决定视觉和交互要求：

1. 用户当前明确要求；
2. 仓库中的项目规范、设计系统和现有产品模式；
3. 目标平台及无障碍标准；
4. 本参考中的通用建议。

不要把通用建议升级成项目硬规则。不得笼统禁止 emoji、固定所有动画时长，或要求所有元素都有同一组交互状态；应根据语义、设备和既有设计系统判断。

## UI Designer

编码前先检查现有页面、组件库、设计 token 和相邻流程。设计方案应覆盖与本次任务相关的内容：

- 页面或组件结构；
- 主要用户路径和信息层级；
- loading、empty、error、disabled、success 等必要状态；
- 键盘、触摸、焦点和屏幕阅读器行为；
- 响应式布局、溢出和长内容；
- locale 切换、RTL、文本膨胀以及日期、数字和货币格式（项目存在 i18n 时）；
- 危险操作的确认与恢复；
- 可被 QA 和体验方验证的成功标准。

只有存在可见界面变化时才输出视觉方案。局部修复优先延续现有设计，不为展示设计能力而重做页面。

## Frontend Builder

实施前：

- 读取相关组件、状态管理、路由、API 客户端和测试；
- 追踪数据从输入到渲染、交互、请求和错误恢复的完整链路；
- 识别与后端共享的类型、字段、状态码和事件契约；
- 确认用户已有改动，避免覆盖无关内容。

实施时：

- 优先复用现有组件和设计 token；
- 保持可访问语义，不用视觉效果替代正确的 HTML/平台语义；
- 明确处理异步竞态、重复提交、组件卸载和请求取消；
- 为用户可恢复的错误提供可操作反馈；
- 只实现已批准范围，不顺手重构无关区域。

设计方案与现有项目规范冲突时，先报告冲突并按更高优先级事实源处理。不得仅因未逐像素照搬文字方案就判定缺陷。

## Frontend Reviewer

先读取真实 diff，再读取受影响组件、调用方、共享类型和测试。不要只审查变更片段。

前后端同时受影响时，Frontend Reviewer 必须拥有独立的 frontend 审查单元。后端问题已修复、接口测试通过或共享契约已更新，都不能自动关闭 frontend 单元；完成下方适用矩阵并写入证据后才能标记 `checked`。

至少覆盖适用维度：

- **正确性**：状态转换、条件渲染、表单值、类型收窄、异步结果；
- **边界与恢复**：空数据、长文本、重复点击、慢请求、失败、取消、卸载；
- **契约**：请求字段、响应解析、状态码、缓存键、事件载荷；
- **i18n / l10n**：硬编码用户可见文本、key/namespace、interpolation/plural、fallback、locale-aware 格式、语言路由与持久化；
- **安全与隐私**：不可信 HTML、URL、日志、token、跨用户缓存；
- **客户端数据出口**：API 请求、analytics、crash/session replay、第三方 SDK、下载/分享、剪贴板和模型调用是否发送原始敏感数据；界面打码不能替代发送前处理；
- **客户端注入**：DOM/HTML、Markdown、URL、模板、postMessage、存储和模型输出进入渲染或导航前的上下文防护；
- **无障碍**：语义、名称、焦点、键盘、触摸目标、对比与减少动画；
- **体验一致性**：是否符合已确认设计、设计系统和相邻产品行为，长翻译、RTL 和窄视口是否截断、遮挡或改变操作语义；
- **性能**：只对可感知或可测量的问题提出性能发现，避免无证据微优化；
- **回归**：受影响入口、浏览器、视口和既有测试。

视觉或交互问题尽可能附真实截图、操作路径或浏览器验证。环境不可操作时，不得声称已经完成真实体验走查。

## 输出

有效发现使用主 skill 的统一格式。没有发现时报告检查范围、验证证据和残余风险。

前端审查通过的最低证据应与风险匹配，可包括：

- 相关单元、组件或端到端测试；
- 类型检查、lint 或构建；
- 真实浏览器操作；
- 关键视口截图或可访问性检查；
- 项目支持 i18n 时至少两个差异明显的 locale、missing key/fallback，以及适用的 RTL 或文本膨胀场景；
- 对无法运行项目时的静态调用链推导。

只运行了构建或类型检查时，不得据此宣称交互和 UX 已通过。

是否允许写入严格遵循主 skill 的“默认修复协议”。获得写入授权后，确认的前端问题应直接修复并用修改后的页面或代码复审，不把问题列表交给用户等待一句“修复”。涉及产品行为取舍、整体视觉改版或破坏用户已有改动时再请求决定。
